# KeyDock

一个原生 macOS 密钥管理器。基于 SwiftUI，macOS 14+，内置官方 Pi Coding Agent 与 Node 运行时，日常使用无需另装依赖。以大模型 API 为主，也能记录其他第三方服务。

## 打开使用

双击 `~/Applications/KeyDock.app`，也可在系统搜索中打开 KeyDock。正式应用只运行一个实例，再次打开会唤醒原窗口。关闭窗口后继续在菜单栏运行，本机代理保持可用；通过菜单栏退出会停止代理。

双击主窗口顶部区域可填满当前屏幕可用区域，再双击恢复原尺寸；不进入绿色按钮的独立全屏空间。窗口正文的选字、控件和图片双击保留各自行为。

日常只有三步：**粘贴添加 → 整理并确认 → 复制使用**。

1. 先复制别人发来的内容，再点击「粘贴添加」，剪贴板中的文字和图片会直接带入。在输入框按 ⌘V 可继续补充聊天、curl、配置或截图，再点击「AI 整理」。图片还可拖入或通过「添加文件…」添加；回复 Agent 时也直接在输入框粘贴。
2. 发送后进入同一次任务的聊天。执行中可以继续发送文字或图片补充；需要你回答时在同一输入框回复。AI 会自主读取文档、必要时写代码分析资料，并按实际响应修正和验证配置。聊天直接显示关键进展，执行过程可展开回看，完整诊断可一键复制。看一眼结果，不对的点编辑；默认只勾选验证通过的条目。同厂商、同用途的多个 Key 各自独立，重复项自动跳过。
3. 选中记录，选一次实际调用模型后点击「复制使用」，即可发给 AI 写代码或用于项目。复制内容包含独立环境变量和完整模型调用 curl，不含真实 Key。同一条 Key 已选过整理模型时会直接复用；其他 Key 分别选择。未选择模型时会提示选择，不再用 `/models` 充当调用示例。

首次使用 AI 时点击「设置 AI」，选择可信 Key 和模型后保存。没有 Key 可在设置中添加，选择厂商预设，只填地址与 Key 即可。设置一次后，后续默认使用该服务，不必反复选择。导入页「整理选项」中用一个「使用 AI 整理」开关切换方式，关闭后仅用本地规则；会记住明确选择的方式。图片需要 AI，没有配置时直接显示设置入口。发送前预览也在整理选项中。仅点击「粘贴添加」不会发起网络请求。

界面采用列表和详情两栏，每条 Key 只有三个页签：

- **使用**：默认打开，模型选择靠右，选择后点击满宽的「复制使用」；下面同一排靠右提供「复制真实使用」和系统变量操作。模型服务只有一个「验证调用」动作，实际请求当前模型，并明确提示少量用量；其他第三方服务按自定义 GET 接口「检查连接」。调用模型后可切换协议；每条 Key 分别记住各模型最后选择的协议，切回模型自动恢复，没有记录的模型默认 Chat Completions。模型 / 协议分别保留最近的验证状态、时间、实际请求和响应，切回后恢复，仍可点击重新验证。换 Key、地址或鉴权配置后不沿用旧结果。请求详情、手动变量与 curl 默认展示，各保留一个整段复制按钮。
- **记录**：查看调用数、Token、最近调用和 Request / Response，正文记录由用户主动开启。
- **资料**：查看密钥、用途、备注、余额和文档，导入原文按需展开，图片随记录加密保存，支持双击放大，重启与加密备份后仍可回显。旧版只有标记 / OCR 的记录无法恢复原图；重新导入相同 Key 并附图时会补回缺失图片，保留原条目与验证结果。密钥字段旁仍可直接复制字段值。

选中新的 Key 会回到使用页，首次打开及收藏排序变化后也会将已选条目滚动到列表可见位置。页面内容宽度设有上限，统一页边距和卡片间距，长资料自然换行，代码单独横向滚动。鉴权、变量名和账单配置仍在编辑中按需展开，备份和批量清理收在右上角菜单中。

详情顶部的归档 / 恢复图标在收藏星标前，旁边保留编辑。详情、右键和批量归档都先确认，取消不会改动记录；恢复可直接执行。左侧每条记录都支持右键操作，归档后的永久删除仍需明确确认。详情的单项更多菜单、完整凭据复制入口、重复的剪贴板按钮和低频单值复制菜单均已移除。

左侧搜索同时匹配名称、厂商、用途、备注、标签、地址、当前模型和已保存模型列表中的所有模型 ID，不只搜索当前选定模型。搜索时名称、厂商直接匹配优先，其他结果在原副标题位置显示命中的模型、用途、标签、地址或备注提示，不增加一行。点击整张卡片切换，列表获得焦点后可用 ↑ / ↓ 选择，自动滚动到选中项；搜索框按 Return 进入首个匹配结果，再用方向键继续切换，搜索编辑及弹框中的按键不切换主列表。没有匹配结果时 Return 保留输入焦点。筛选中新增 / 导入条目后会显示新条目，空分类提供准确说明及查看全部 / 归档的入口。搜索框可一键清空，备注及附加 Header 使用全宽、左对齐的多行输入框。所有折叠区支持点名称及整行展开 / 收起，导入与编辑弹框也使用相同样式。

右键删除其他条目会保留当前正在看的详情。已到期但未归档的 Key 可以主动核验；设置的到期时间仍会阻止项目调用，验证通过不会自动延长该日期。批量操作名为「检查全部连接」，不自动发送模型生成请求；需要模型调用才能核验的服务会提示单独选择模型验证。连接检查成功显示「连接正常」，模型请求成功显示「调用通过」。结果只展示一次，下方直接提供 HTTP 状态及请求 / 响应切换，失败时显示服务的具体原因；网络失败同样保留已尝试的请求。

## 同一厂商、多条 Key、多项目同时使用

每条记录有一个可编辑且不可重名的变量前缀，以及基于 UUID 的固定本机路由。比如两条 DeepSeek：

```bash
export DEEPSEEK_WORK_01_BASE_URL='http://127.0.0.1:47831/s/第一条记录的UUID'
export DEEPSEEK_WORK_01_API_KEY='keydock-local-第一条记录的UUID'

export DEEPSEEK_WORK_02_BASE_URL='http://127.0.0.1:47831/s/第二条记录的UUID'
export DEEPSEEK_WORK_02_API_KEY='keydock-local-第二条记录的UUID'
```

「复制使用」和系统变量使用上述本机占位配置，上面 UUID 只是说明。这些行可直接在终端执行，或保存到配置文件后 `source 文件路径`。每个项目选择自己需要的前缀即可，不必覆盖同一个 `OPENAI_API_KEY`。「复制真实使用」则包含真实凭据，直接连接上游服务。

```python
import os
from openai import OpenAI

work = OpenAI(
    base_url=os.environ['DEEPSEEK_WORK_01_BASE_URL'],
    api_key=os.environ['DEEPSEEK_WORK_01_API_KEY'],
)
test = OpenAI(
    base_url=os.environ['DEEPSEEK_WORK_02_BASE_URL'],
    api_key=os.environ['DEEPSEEK_WORK_02_API_KEY'],
)
```

应用会把别名路由到对应 Key 的上游地址并注入真实鉴权。替换记录中的真实 Key 不需要修改项目配置；修改变量前缀后，旧终端已加载的变量仍有效，固定路由不变。归档、到期后路由拒绝新请求，恢复 / 修改到期日期后可继续使用。

点击详情中的「添加系统变量」即可为当前用户安装这条 Key 的变量，按钮随后变为「移除系统变量」；「环境变量与 curl」仍可手动复制。新开的终端、重新启动的 IDE / GUI 应用可读取变量，已运行的进程需要重启。重新登录时会恢复这些变量，但仍需保持 KeyDock 运行以使用本机代理。

只写入本机地址、占位 Key 和模型名。管理文件在 `~/.config/keydock/`，重新登录的任务在 `~/Library/LaunchAgents/local.keydock.environment.plist`；Shell 配置只添加一条受管理的 source 行，保留已有配置和 Bash 登录文件的优先级。移除时只清理本程序管理的内容，其他程序已经改写的变量不会被覆盖删除。

国内兼容接口（千问、豆包、Kimi、DeepSeek、百川及兼容中转）可采用上面的 OpenAI SDK 接法，模型名称填写该服务控制台提供的值；豆包也可填写推理接入点 ID。代理保留 `/compatible-mode/v1`、`/api/v3`、Coding Plan 与租户路径前缀，不会根据模型名称改投官方地址。百炼的地域、业务空间以及 Coding Plan 地址和 Key 必须相互对应，请按控制台提供的地址填写。

接入 Anthropic SDK 时同样将本机地址作为 `base_url`、占位 Key 作为 `api_key`；代理会消除相同 `/v1` 在拼接边界的重复。Gemini SDK 可通过 `http_options` 指定本机 `base_url` 和与保存地址一致的 `api_version`（常见为 `v1beta`）。自定义服务支持 Header 鉴权；需要签名、OAuth 自动刷新等服务可记录资料，但未实现其签名和刷新流程。

## 厂商预设、模型与协议

预设保留 DeepSeek、百炼、火山方舟、Kimi、百川、百度千帆和 EOS 四个地域。它们共用已核对的接入资料，自动填写文档、已确认的模型目录和可复用同一 Key 的余额配置；手动填写已知地址后保存，也会补齐空白字段。未确认的接口、需要独立云账户鉴权的余额查询会说明原因，并提供控制台入口。资料、来源与匿名核验范围见 [PRESETS.md](PRESETS.md)。

调用模型后方可切换 Chat Completions、Messages、Responses，默认 Chat；已知厂商按已核对能力显示协议，其他中转站可自行选择，EOS 另支持 Gemini 原生协议。切换会更新实际接入地址和鉴权、清除旧调用通过状态，保留同一 Key 的模型和固定本机别名。代理按项目实际请求的协议路由，旧项目不会因为界面切换而改用另一个协议。

「添加模型…」添加并选择新模型，已有模型会保留；当前模型、手动保存模型与接口目录合并去重，单个模型也可复制列表。编辑中可按行增删手动模型，目录刷新不会抹掉它们。已知厂商的同一 Key 不因协议或版本前缀不同重复录入；不同地域、Key 或辅助鉴权仍分开。

普通 curl 示例移除可选输出上限；原生 Messages 只保留协议要求的必填项，已确认可选的 DeepSeek、火山方舟例外也会移除。内部验证仍使用小用量请求，已记录请求保持实际发送的参数。

## 智能整理

- 本地识别：提取 Base URL、Key、curl、文档、用途、备注、模型、Header、到期日期。不执行 curl 或任何 shell 内容。
- AI 整理直接集成官方 [`@earendil-works/pi-coding-agent` 1.5.0](https://github.com/earendil-works/pi)，底层是官方 `pi-agent-core`，由它管理自主规划、工具执行、观察反馈与后续决策，不另写固定处理流水线。模型请求直达用户选择的服务，无应用方云端中转；支持 Chat Completions 兼容接口、Anthropic Messages、Responses 和 Gemini GenerateContent，所选模型需要支持工具调用。
- Agent 系统提示词从代码中独立为 Markdown。可在「系统设置 → 智能整理 → 编辑提示词…」编辑、保存或恢复默认，也可直接修改 `~/Library/Application Support/KeyDock/AgentPrompts/credential-import.md`。两处使用同一份文件，每次新任务重新读取，无需重启或重新打包；运行中的任务使用开始时的版本。首次使用从随包默认值创建，之后应用升级不覆盖；恢复默认先载入编辑框，保存才写入文件。配置只包含提示词，不要填入真实密钥。
- 项目中的默认值在 `AgentRuntime/prompts/credential-import.md`，用于首次初始化和恢复默认；日常调试修改外置文件即可。工具参数、凭据来源核对和真实验证仍由宿主执行，不依赖模型口头声明。可运行 `zsh scripts/test.sh --agent-prompt-checks` 验证文件读取、更新保留、任务间重读及原生编辑保存。
- Agent 使用官方 read / write / edit / bash 工具，可以自行编写并执行临时 JavaScript 或命令来解析复杂资料；另提供查询厂商接入参考、读取文档、提出候选、实际验证和提交结果的原生工具。文档与错误返回作为数据处理，不能仅凭模型口头声明标记验证成功。网络验证由宿主注入真实鉴权，脚本不通过命令行或环境变量接收真实 Key。
- 本机会给已识别密钥和疑似不透明值分配片段编号，由 AI 根据上下文判断哪个是 API Key、tokenId、模型等，再在本机还原。未知格式仍可能遗漏，可在发送前预览、修改。所选整理服务自身的 Key 只用于请求该服务的鉴权。
- 图片直接出现在文本框内，可在图片前后继续编辑，双击放大查看，右键移除或选中后按 Delete；撤销 / 重做会同步恢复实际待发送的附件。图片以实际图片数据发送，所选模型需支持图片输入。图片中的文字不自动脱敏，可能包含真实密钥。单次最多 6 张、处理后总共 10 MB；会缩放为最长边 2560 像素的 JPEG，原文件不改动。复制出的本地图片路径会读取为附件；路径失效时会提示重新添加。
- 图片中的文字可由本机 Vision 生成索引以核对地址，理解任务仍由 AI 完成。确认保存后，实际用于整理的规范化图片随导入原文加密保存，可在资料中回看；文字索引用于整理与来源核对，不重复堆进新记录的原文。图片提取的密钥若无法核对会明确注明，保存前请对照原图。
- 文本密钥需对应片段编号或原文中的确切值；图片识别值可以提交实际验证，不以本地 OCR 是否识别密钥作为前置条件。基础地址需有用户资料、图片文字索引或已获取文档中的来源，无法确认则留空。文档示例 Key 不能替代用户提供的 Key。
- 文档工具获取用户提供或已获取文档中出现的链接，不携带 API 鉴权或浏览器 Cookie；支持网页、文本、JSON 和可提取文字的 PDF。公开文档可使用任务独立的匿名访客 Cookie 跟随跳转，不复用或污染 API 会话，任务结束后销毁。飞书 SSR 页面提取正文供读取，同时保留原始文件，嵌入表格仍需继续获取；只有标题或登录页不能声称读完。需要登录或未获得正文时会说明，可粘贴正文或截图，程序不读取浏览器登录态。
- 验证使用实际服务响应，优先进行小用量模型请求；可按文档调整相对路径、JSON 参数与必要 Header。HTTP 200 不直接等于模型调用成功。验证通过的请求格式会保存并用于复制 curl，避免验证与示例不一致。限流、额度、权限或未确认的响应不会伪装成通过。
- 整理始终留在同一页。Agent 未完成时直接显示它的实际回复和服务返回的错误；你可以回复、纠正、补充文字 / curl / 截图，继续同一个官方 SDK 会话，不必重新粘贴原资料。确实缺资料时会列出具体问题、原因和示例；也可不补资料，直接让它继续尝试。
- 备注可以为空，通常只保留一至三条特殊接入要求、已知限制或实际待解决事项；地址、鉴权、模型目录与验证状态由专用字段维护。只改名称、用途、备注和标签会保留当前请求的验证结果；修改连接、鉴权、协议或模型后重新验证。
- 已有部分结果时，可以继续对话，或点击「查看当前结果」。运行时异常退出也会保留宿主已产生的候选与实际核验状态，显示具体失败原因，并在同一页提供重试、补充资料和调整设置的入口。结果保留未解决候选和实际原因，未验证条目默认不能勾选保存，可编辑后重新验证；本地规则识别与手动添加仍可保留不完整资料。顶部「停止」终止当前执行并保留聊天、输入和已有结果；停止期间禁用重复操作，收尾完成后可继续补充。底部「关闭」独立关闭任务页。Esc 在执行中停止，⌘W 关闭任务页并取消后台执行；停止本身不关闭页面，不弹取消失败提示。返回修改后可直接回到已有整理结果；取消或关闭时会取消仍在运行的草稿验证。以上未保存的整理状态只在本次打开的窗口内保留，关闭应用前仍需确认保存。
- Agent 可查阅与当前厂商、地域和真实业务空间匹配的接入参考，再按需要读文档和探测；资料明确写出 EOS 地域时可使用相应参考，地域含糊时继续确认，不猜测。参考资料不是调用通过证明。备注只提取并润色接入要点、使用限制、待确认事项，空分组不显示，不复写地址、Key、模型和整段原文。完整原文仍单独保留。
- 第一次使用需明确设置可信服务；之后记住服务和模型，不自动切换厂商。Agent 的多轮整理和实际探测会产生正常用量。界面只显示简短进度，过程在确认页按需展开。
- Agent 会话在内存中运行，每次使用独立临时目录；运行进程和子命令受 macOS 文件访问限制，只能写任务目录、读取运行时与必要系统文件，不加载个人 Pi 配置或扩展。公开网络可用于获取资料；同一用户下的其他恶意程序不在此隔离保证内。预算为每次累计运行最多 10 分钟（等待用户回复不计时）、32 个模型轮次、96 次工具动作、30 次探测和 8 份文档，以控制失控循环与费用，不规定动作顺序。任务结束或停止后清理任务文件。

## 复制、分享与编辑

- 「复制使用」提供本机配置；「复制 curl」可单独使用，不必先手动设置变量。命令优先读取每条 Key 的独立项目变量，变量未设置或为空时使用本机别名默认值，仍不含真实 Key。接口路径与 JSON 正文按字面传给 curl，不当作 Shell 代码执行。
- 「复制真实使用」提供真实 Base URL / API Key / 模型环境变量和实际模型调用 curl，沿用当前协议、鉴权、附加 Header 与请求模板；不需要 KeyDock 运行，也不计入本机代理的记录。自定义服务提供真实配置及鉴权 Header，具体路径和正文按服务文档填写，不虚构模型请求。内容不包含备注、批量原文、历史、余额或本机路由。旧版已复制的 JSON 凭据仍可导入，导入不继承验证通过状态。
- 编辑备注或名称会保留原有服务协议和有效验证结果，厂商标签不等同于网关协议；编辑器按实际请求模板显示协议。切换预设会清除旧服务的模型、请求模板、Header、验证和余额配置；若切换到不同域名，还会清空旧 Key 并提示填写对应密钥。手动修改服务地址时，会替换仍沿用旧预设的文档、目录和余额地址，保留自行填写的自定义接口。新条目先粘 Key 再选预设时会保留刚粘的 Key。
- 两种使用配置采用相同的可用条件，资料不完整或模型未选择时显示原因；资料未补齐时不安装无法工作的系统变量，也不能选择它作为整理服务。
- 已知预设的同一地域、同一 Key 不因常规协议或版本路径不同而重复导入，独立地域、附加鉴权和未知中转地址仍分别判断。重复导入会定位已有条目，条目在归档中时显示归档；恢复后自动回到活动列表并保留选中项。旧版留下的重复条目仍可编辑，新建重复项会被阻止。导入前手动指定的有效变量前缀会保留，重名时自动追加数字，避免覆盖其他项目。
- 验证、读取模型列表或查询余额期间修改名称 / 备注，会保留正在完成的结果；修改密钥、鉴权或相关接口后，旧结果不再回填。导入草稿同样处理验证与编辑交错，修改验证地址后需要重新核验。批量验证轮到每条 Key 时读取当前配置，跳过已删除或归档项。

## 验证、归档与余额

- 智能整理设置与发送前预览共用模型选择：可手填、从缓存选择、获取 / 刷新或复制列表。切换 Key 会取消旧请求，旧响应不会回填到新服务；刷新失败保留原列表并就地显示错误，不阻止手填模型。
- ⌘F 直接定位搜索，已有弹框时不抢走弹框中的输入焦点；添加模型、查看日志等详情弹框打开时，主窗口的新建、粘贴添加和列表快捷键也不会干扰当前操作。过期和归档条目的「复制使用」及模型 curl 操作在详情与右键菜单保持一致；其他第三方服务仅展示适用的环境变量，不套用模型聊天示例。

- 「调用模型」只有一个下拉框：选择模型、获取 / 刷新列表、复制列表和手动填写都在其中，管理动作位于长列表前。尚未取得目录时，当前已配置模型也会列出并可复制，只有一个模型同样可用；不把它冒充完整支持清单。智能整理设置和预览页沿用相同规则。实际调用、切换模型或修改备注不覆盖列表，接入地址、Key 或鉴权改变后清除旧缓存。
- 修改模型目录的查询地址会清除旧接口发现的列表，保留当前模型和手动保存的模型；旧查询迟到的结果或错误不会进入新配置。整理设置和导入确认页采用相同规则，只改备注不会中断正常查询。
- Agent 整理完成前会尝试获取接口返回的模型目录，即使已经知道默认模型；获取失败保留已知模型并说明，不逐个付费调用所有模型。目录不支持时，Agent 可提交在用户资料或已读取文档正文中逐字核对的具体模型 ID，标记「来自资料，调用权限需验证」。不接受编造名称、应用界面翻译中的名称或敏感片段，也不把其他地区的模型套给当前 Key。接口只返回当前页时，仅代表该页，不承诺全站清单或全部调用权限。
- 本机代理支持将条目 Base URL 后的 `/models` 转给上游，必须保留 `/s/条目编号` 路由并使用本机占位 Key；不提供任意根路径探测接口。上游未提供目录或路径不正确时可返回 404，不等于模型调用必然失败；程序不伪造完整目录。
- 应用弹框支持 ⌘W 和 Escape：⌘W 关闭最上层弹框；Escape 执行当前页的「取消 / 停止」，整理运行中只停止并保留资料，其他时候关闭弹框。输入法正在组词时，Escape 先取消组词。主窗口关闭后继续留在菜单栏。

- 模型服务的主动作统一为「验证调用」，向当前模型发送简短实际请求并明确提示少量用量；只证明此次模型调用。其他第三方服务按自定义 GET 接口「检查连接」。全局「检查全部连接」不自动调用模型，不能通过目录核验的记录会提示单独验证，不因此判定 Key 失效。
- 验证、复制配置、旧模板重新调用和 Agent 请求统一省略可选的输出限制参数（`max_tokens`、`max_completion_tokens`、`max_output_tokens`、Gemini 的 `maxOutputTokens`），使用服务默认值。仅保留 Messages 协议要求的必填项，已确认可省略的 DeepSeek / 火山方舟 Messages 也不发送。验证继续使用简短输入；用户程序经代理发送的原始参数和历史请求记录保持真实。
- Responses 返回 `incomplete` 且已经产生回答或推理内容时，显示「调用通过」并注明输出尚未完整结束，不再误报为需要检查；空输出、未完成的排队状态或实际错误仍分别判断。请求 / 响应详情保留服务的实际状态和未完成原因。
- 「连接正常」与「调用通过」区分连接查询和模型请求；归档显示「已归档」，到期状态仍会阻止项目调用。验证卡片直接显示请求 / 响应切换，可查看完整 curl、响应 Header、正文及服务错误原因。默认隐藏敏感值，在系统设置中开启「显示完整密钥与请求内容」后，详情、编辑器、验证结果及调用记录统一显示原始值。复制响应与当前显示一致，复制请求 curl 包含真实鉴权并按敏感剪贴板处理。新记录在本机加密保存实际请求和最多 128 KB 的原始响应；旧数据缺失请求或响应时明确说明，不冒充原始记录。
- 当前模型实际调用通过后，后续连接检查单独保存结果和请求，不因目录不支持、目录查询成功、超时或目录权限受限而覆盖上次调用结果。页面明确显示上次调用时间，并提示最近连接检查情况，原因和请求放在同一请求详情内。服务明确返回鉴权失败仍正常更新状态；修改 Key、鉴权或相关核验配置会清除旧证据，切换模型不能继承另一个模型的调用通过。批量检查始终不发送模型生成请求。
- HTTP 401 只有同时返回明确的鉴权错误码时才列为鉴权失败；含糊的中转登录页、未支持的模型列表、地域和地址问题不会仅凭 401 判定失效。403、402/429、网络异常、404 和服务错误分别提示。
- 批量清理只列出用户设置已到期或明确鉴权失败的记录，归档前可勾选并确认。窗口打开后恢复正常的条目会退出勾选范围，确认时再次以最新清理条件过滤；不会归档已从清理列表消失的记录。归档可恢复，永久删除仅在归档中明确执行。
- 永久删除会同步清理该 Key 的调用记录、累计统计、正文记录开关、系统变量和整理服务引用。确认框打开后条目已恢复或被编辑时拒绝删除，需重新检查；归档保留资料与记录，恢复后可继续使用。
- DeepSeek 官方 `api.deepseek.com` 可查询余额。其他服务在高级选项填写 GET 查询地址、JSON 字段路径和单位；不提供接口的服务不显示虚构使用数据。
- 自定义验证 / 余额地址会收到该记录的鉴权，请填写对应服务可信的地址。不自动跟随重定向，不向导入的文档地址发送密钥。

## 调用统计与排错

在条目的「记录」页，可查看累计调用数、成功数、输入和输出 Token，以及最近调用的状态码、模型和耗时。仅覆盖经过 KeyDock 本机代理的请求；直接调用官方 API、智能整理与验证的直连请求不计入。用量取服务返回的 usage，不估算缺失用量，不代表官方账单。部分累计用量会用 `+` 标识；SSE 也需要上游返回用量数据。

默认只记录状态、耗时和用量。可在每条 Key 的记录页开启正文记录，也可在系统设置中开启「为所有 Key 记录请求与响应」，覆盖现有及后续新添加的 Key。开启后，后续本机代理调用可查看 Request / Response 的 URL、Header、JSON 或 SSE 片段。全局记录开启时，单条开关显示为已开启且不可单独关闭；关闭全局开关后，沿用原来的单条选择。原始内容在本机加密保存，是否隐藏鉴权 Header、Cookie 和已知 Key 由全局显示偏好控制。调用记录使用同一钥匙串主密钥加密：`history.kdv` 保存最近 5000 条索引与统计，正文在 `history-bodies/` 中逐条压缩加密，后台写入、打开详情时按需读取。每段请求 / 响应正文最多 2 MB，旧版已截断或未记录的内容无法补回。列表每页 10 条，支持前后翻页、首页 / 末页和输入页码跳转。详情支持 JSON 与 SSE 格式化、中文 Unicode 转义还原、原文切换、全选及复制；复制遵循当前完整内容开关。明细自动淘汰不影响累计统计，「清空…」可清理当前 Key 的数据。加密密钥备份不包含调用日志。

代理复用一个独立的上游连接池（HTTP/1.1 每主机最多 64 个连接，支持系统 HTTP/2 多路复用），最多接收 256 路客户端并行连接，请求缓冲总额限制为 128 MB；满载返回明确的 503。SSE 收到数据后立即按块转发，不等待整段完成，单路取消只取消对应上游任务。上游无数据等待为 1 小时，单次总时限为 24 小时；客户端自身仍可设置更短超时或取消。代理超时返回 504 并记录系统错误域 / 错误码，上游实际返回的 502 保留原状与来源。代理不主动重复发送模型请求。上传支持 Content-Length、chunked 及 100-continue；上传连续 60 秒没有新数据才返回 408，持续上传不受此时长限制。停止会取消当前连接，立即重启会等旧监听端口释放后再接收新请求。

正文写入落后或磁盘暂不可用时，待写入正文的内存缓冲上限为 64 MB，优先保留最新正文；超额只保留调用摘要与统计，详情会说明正文缺失原因。恢复存储后可重试保存。查看详情独立读取文件，不等待正文写入队列；关闭详情会取消未完成的读取任务。

调用列表只在底部保留一组分页。详情在后台准备并缓存请求、响应的原文与格式化版本；切换保留各自滚动位置和选择。大正文只排版可见行，超长单行也可换行、拖选、⌘A 全选和复制完整内容；复制依据源文本，不因可见区域而截断。显示隐藏设置改变后会清除旧缓存并重新准备。格式化展开超过 8 MB 时保留原文并说明原因，避免复杂数据导致大量展开。

导入原文和验证详情也支持大段内容的后台准备、全选与完整复制。读取文件时显示进度，关闭后取消读取；图片缩略图与长输入资料可重复使用，减少切换和重绘时的等待。搜索结果随记录更新，修改模型、收藏或归档后立即生效。

清空记录后，此前已发起但尚未结束的请求不会把旧记录重新补回来，新请求正常计入。持续调用时会定时保存；读取或保存失败会显示提示，可在解锁钥匙串或恢复文件 / 磁盘权限后点击重试，原加密文件保留。

默认隐藏时，也检查已知 Key 的常见 JSON 转义与 URL 百分号编码。显示偏好只影响本机展示和普通复制，不改写实际请求或已保存的原始值；开启后可即时查看完整内容。旧版本已经替换成「[已隐藏]」的历史值无法还原，需要重新验证或发起调用。正文记录偏好只影响后续调用，不补录以前的正文，也不删除已有记录。手动验证的实际请求与响应仍作为验证依据保存。

## 整理运行日志

聊天展示关键进展，诊断记录用于排查。运行时显示最近三个关键步骤，结束后收成可展开的过程摘要；「查看过程」展开所有关键步骤。聊天共用一个滚动区域，上翻阅读时保留位置，「回到最新消息」返回末尾。输入和发送操作固定在底部，长文字或图片输入会适度增高。完整诊断通过「复制全部日志」一次复制，包含任务信息、输入资料和已记录的请求、工具参数与结果；容量淘汰和详情截断会标注。屏幕与复制内容遵循全局完整显示开关，整理模型请求保留实际发送的 KEYDOCK_SECRET 编号，不将本地密钥还原冒充发送原文。

后台自动把每次整理的诊断记录写入 `~/Library/Logs/KeyDock/Agent/*.json`，可在系统设置的智能整理区域点击「运行日志」打开目录。以后排查可直接读取最近文件，无需解密正式保险库或重新复现问题。包括版本、模型、协议、已脱敏输入、同一任务的对话上下文、工具参数 / 结果、实际验证 curl / HTTP 错误、运行时错误及耗时；请求副本排除内部推理和图片，后续模型请求只记录最新消息并明确标注省略的历史，初始上下文与工具定义保留在首次请求中；执行中定时保存，完成、失败或停止时立即保存。日志默认记录，独立于项目代理的「记录请求与响应正文」开关；不会把此开关自动打开。

日志文件仅本机当前用户可读写，密钥和鉴权字段脱敏，不记录图片二进制 / base64，业务文字仍会留在本机日志中。最多保留最近 20 次，每次最多 250 条 / 约 512 KB 事件正文，每条详情超过 12,000 字时明确截断。该诊断目录不包含在密钥备份中；项目调用明细继续单独在加密的 `history.kdv` 中保存。

## 系统设置

从应用菜单「设置…」（⌘,）、主窗口更多菜单或菜单栏入口打开。集中管理全局显示、全局调用正文记录、智能整理服务和 Agent 提示词；模型、协议、余额地址仍放在各 Key 的详情中。两个全局开关默认关闭，即时保存，重新打开应用后保留。加密备份包含偏好，正常合并恢复不覆盖已有的明确选择；外置提示词文件独立保存，不包含在保险库备份中。显示完整内容不改变给 AI 的密钥占位处理，也不改变「复制使用」的本机别名配置。

## 数据与安全边界

- 全部记录（包括 Key、curl、备注、原文）使用 AES-256-GCM 加密，存放于 `~/Library/Application Support/KeyDock/vault.kdv`。
- 加密主密钥由 macOS 登录钥匙串保存，服务名 `local.keydock.vault`，账号 `master-key-v1`。文件权限 600，目录权限 700，不使用云同步，不上传遥测。
- 保存使用文件锁和文件版本检查。其他副本已经修改数据时会刷新并拒绝覆盖，请重试；打开的旧编辑页不能覆盖更新后的记录或重新创建已删除记录。编辑描述信息会保留最新的验证和余额结果。
- 旧窗口发起验证、余额或系统变量操作前会检查最新条目。导入时会处理编号冲突，去重忽略主机名大小写、标准端口和首尾空白，保留路径大小写与导入原文。
- 「加密备份与恢复」使用独立密码、随机 salt、PBKDF2-SHA256（310,000 轮）与 AES-256-GCM。备份可迁移至其他 Mac，遗失密码无法恢复。恢复合并条目且去重；保险库无法解密时可从备份恢复，原文件自动保留。
- 保险库无法打开时，备份窗口直接进入恢复模式，保留原文件并用所选备份重建保险库；正常恢复则合并去重。恢复会带回整理方式设置，已有的明确选择优先保留。
- 默认「复制使用」不含真实 Key。已知鉴权信息用于本机显示隐藏、占位配置及 AI 上下文保护；错误填入模型名称的已知鉴权内容会阻止继续发送。已管理的系统变量在启动时同步，只更新 KeyDock 自己登记的条目，不覆盖其他用户变量。「复制真实使用」明确复制真实连接配置，资料字段旁仍可复制单个 Key；请求 curl、响应及真实凭据的显式复制在 45 秒后、剪贴板未变化时清空。退出应用时也会清理本人复制且尚未变化的敏感内容，无法清除第三方剪贴板历史。完整内容显示由系统设置统一控制，不再使用单条的 20 秒显示开关。
- 本机代理由 KeyDock 提供，只监听 `127.0.0.1:47831`，拒绝浏览器 Origin / Fetch 请求，要求匹配条目占位 Key；不监听局域网，不经过应用方服务器。调用日志仅本机加密保存，正文默认不记录；完整内容是否显示由系统设置统一控制。
- 代理支持 JSON / 普通 HTTP 请求、分块上传及 SSE 流式响应，原样转发协议，不做跨协议转换。最大请求体 20 MB、最多 256 路客户端连接；WebSocket / 协议升级明确返回 501。转发调用会正常产生服务用量。
- 路径和查询保留百分号编码，例如 `%2F`、`%2B`，避免改变业务参数。模型接口不转发客户端的鉴权查询参数；自定义服务会保留名为 `key` 的业务参数，并过滤本机占位凭据。
- 本地别名不是可在其他机器使用的真实凭据，但在本机可以调用服务并消耗额度。拥有本机执行、调试或钥匙串权限的 AI / 程序仍可能访问数据或调用代理，此工具不隔离同一用户下的恶意代码。给 AI 写代码时只提供本机接入配置，避免提供真实密钥、原文和保险库数据。
- 支持用户明确填写的 HTTP / HTTPS 网关，保留原协议，不擅自升级为 HTTPS；鉴权请求仍不自动跟随重定向。没有签名公证的本地开发构建可能显示 macOS 安全提示；应用使用本地 ad-hoc 签名；重新编译更新后，macOS 可能要求重新授权钥匙串访问。

## 从源码构建

构建需要 Apple Command Line Tools、Node 22.19+ 与 npm，不需要 Electron 或 Xcode 工程。安装后的应用自带 Node 和锁定版本的官方依赖，用户无需安装这些开发工具。

```bash
cd KeyDock
npm ci --prefix AgentRuntime --ignore-scripts --no-audit --no-fund
zsh scripts/test.sh
zsh scripts/build-app.sh
zsh scripts/install-app.sh
open "$HOME/Applications/KeyDock.app"
```

构建只在 `dist/` 保留 `KeyDock.zip` 安装包，安装脚本直接解包至 `~/Applications/KeyDock.app`，避免系统搜索收录两个应用；旧版 `dist/KeyDock.app` 会在成功生成安装包后移除。

源码分为 SwiftUI 界面、导入解析、服务请求、本地代理、加密存储与测试。`dist/` 和 `.build/` 为生成内容，已列入 `.gitignore`。请不要把真实凭据、备份或保险库文件提交到代码仓库。

测试使用自带检查程序，不依赖完整 Xcode 的 XCTest。最新覆盖范围、SDK 接入测试和连续请求结果见 [TESTING.md](TESTING.md)。
